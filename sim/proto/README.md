# Lite3 3D 시뮬 프로토타입 (Windows 동작 확인)

실제 Lite3 3D 모델이 **공식 사전학습 보행 정책**으로 걷고, 학생용 API(`dog.forward(1.0)`)로 조작된다.

## Lite3 Studio (추천) — 편집기와 3D 시뮬레이터를 한 창에서
`run_studio.bat` 더블클릭 (또는 `../../.venv/Scripts/python studio_web.py`)
- 앱 창(최대화) 하나에 **왼쪽은 코드 편집기와 출력**, **오른쪽은 3D 로봇과 조작 패널**이 함께 있다. 칸 사이 경계를 끌어 크기를 조절할 수 있다.
- **샘플**에서 기본 예제와 J1–J5를 고르고 **▶ 실행(F5)** 을 누르면 오른쪽 3D 화면의 로봇이 바로 움직인다. 시뮬레이터는 계속 켜져 있어 로봇 상태가 실행 사이에 이어진다.
- **■ 정지(Esc)**: 무한 반복도 약 0.6초 안에 멈춘다. 응답이 없으면 3초 뒤 시뮬레이터를 다시 켠다.
- **↺ 처음 자세**: 로봇을 엎드린 처음 상태로 되돌린다.
- 3D 화면: 마우스 왼쪽 드래그로 회전, 휠로 확대, 오른쪽 드래그로 이동. **카메라 따라가기**를 켜면 걷는 로봇을 따라간다. 화면 위에 몸 높이, 기울기, 발 4개가 받는 무게, 넘어짐 경고가 표시된다.
- 오류가 나면 편집기의 해당 줄이 빨갛게 표시되고, 출력창에 "내 코드 N번째 줄"로 알려 준다.
- **저장·열기**: `문서/Lite3Studio` 폴더에 저장한다. 편집 중인 코드는 자동으로 기억되어 다시 열면 이어서 쓸 수 있다.
- 구성: `studio_web.py`(웹 서버, aiohttp) ⇄ WebSocket ⇄ `web/`(three.js 3D, CodeMirror 편집기) / `studio_web.py` ⇄ `sim_server.py --stream`(MuJoCo 물리 + 학생 코드 실행). 3D 모양은 물리 시뮬과 같은 공식 MJCF 메시를 쓴다. 화면 라이브러리는 `web/vendor/`에 들어 있어 인터넷 없이도 동작한다.
- pywebview 앱 창을 열 수 없는 PC에서는 기본 브라우저로 열린다(`--browser`로 강제할 수 있음).
- 예전 tkinter 버전은 `run_studio_classic.bat`로 실행한다.

### 조작 패널 (코드를 몰라도 값의 뜻을 눈으로 확인)
Lite3 Studio 오른쪽 아래에 있다(클래식 버전은 🎛 버튼으로 별도 창).
- **서기·앉기**는 몸이 낮거나 기울어 있으면 먼저 엎드렸다가 일어선다(공식 StandUp 상태와 같은 방식). 바로 다리를 펴면 한쪽으로 쏠린 자세에서 뒤로 넘어지기 때문이다. 넘어진 상태에서는 걷기를 시작하지 않는다.
- **로봇 상태**: 몸 높이, 기울기, 발 4개가 받는 무게(kg), 엎드리기·서기·앉기 버튼, 모터 강성 kp 슬라이더(낮추면 몸이 처짐)
- **① 관절 하나씩**: 다리를 고르고 `옆으로 벌리기(hip_x)`, `앞뒤로 흔들기(hip_y)`, `무릎 굽히기(knee)` 슬라이더를 움직인다. 옆·뒤에서 본 다리 그림에 목표(점선)와 실제(굵은 선)가 보인다.
- **② 발 위치로**: 그림의 빨간 발끝을 마우스로 끌면 역기구학으로 각도를 계산해 움직인다. 닿을 수 없는 위치는 빨간 글씨로 알려 준다.
- **③ 걸음새**: 주기·보폭·발 드는 높이·딛는 깊이를 슬라이더로 바꾸며 트롯으로 걷게 하고, 발끝 궤적과 이론 속도를 본다.
- **코드로 쓰면**: 방금 바꾼 값이 코드 한 줄(`dog.set_angle("FL", "knee", 110)`)과 딥 로보틱스 공식 형식(관절 2번 `FL_Knee_joint`, 1.920 rad)으로 표시된다. **편집기에 넣기**로 그대로 가져갈 수 있다.
- 코드 실행 중에는 패널로 조작할 수 없다(상태 표시는 계속 갱신됨).

### 무게중심 (④ 탭, 3D 화면)
- 3D 화면에 **노란 점 = 무게중심**(짐 포함 로봇 전체), 바닥까지 점선과 바닥 표시, **지지 다각형**(바닥에 닿은 발을 이은 영역)이 보인다. 색 의미: 초록 = 안정(무게중심이 안쪽), 빨강 = 밖(넘어짐), 주황 = 두 발 지지(트롯처럼 움직이며 균형). "● 무게중심 보기"로 켜고 끈다.
- 화면 왼쪽 아래와 ④ 탭에 **무게중심 여유(cm)**가 표시된다. 지지 다각형 가장자리까지의 거리이고, 음수면 밖이다.
- ④ 탭에서 **짐**(0–5 kg, 앞뒤 ±20 cm, 좌우 ±12 cm)을 몸통 위에 올려 무게중심을 옮긴다(시뮬레이터 전용). 위에서 본 그림에 발(닿음 ●/떠 있음 ◌), 지지 다각형, 무게중심, 짐이 그려진다.
- 학생 코드: `dog.get_com()`(무게중심 x, y, z m), `dog.get_com_margin()`(여유 cm, 음수 = 밖), `dog.set_payload(kg, x=0.0, y=0.0)`(시뮬레이터 전용). `Robot`과 `JointDog` 모두 사용할 수 있다.
- 측정 예: 서 있을 때 여유 +15.3 cm → 앞왼쪽 다리를 바로 들면 −10 cm(넘어짐), 몸을 뒤로 옮긴 뒤 들면 +6.1 cm(버팀). 5 kg 짐을 뒤-오른쪽에 실으면 발을 옮기지 않고도 앞왼쪽 다리를 들 수 있고, 앞쪽에 실으면 뒤집힌다.
- 구현: 짐은 공식 MJCF에 덧붙인 `PAYLOAD` 바디(`lite3_sim.load_model`, MjSpec)이다. 기존 바디·관절 번호는 그대로이고 짐이 없을 때 질량은 0.1 g이다. 무게중심은 MuJoCo `subtree_com`으로 구한다.

## 딥 로보틱스 공식 인터페이스
`lite3_interface.Lite3SimInterface`는 공식 `interface::RobotInterface`(Lite3_rl_deploy)와 함수 이름, 단위(rad), 관절 순서(FL_HipX…HR_Knee), 명령 형식(`SetJointCommand` 12×5 = [kp, 목표각, kd, 목표속도, 보조토크])이 같다. 학생 API(`JointDog`)와 조작 패널은 모두 이 인터페이스를 거쳐 시뮬을 움직인다. 고급 학생은 `dog.robot`으로 직접 쓸 수 있다.

## 명령줄 실행
```bash
# 저장소 루트에서 (최초 1회)
bash scripts/clone_upstream.sh          # 또는 Lite3_rl_deploy 만 --recurse-submodules 로 클론
python -m venv .venv
.venv/Scripts/python -m pip install -r sim/proto/requirements.txt

cd sim/proto
../../.venv/Scripts/python demo_square.py            # 3D 화면 (창을 닫으면 종료)
../../.venv/Scripts/python demo_square.py --no-view  # 화면 없이 결과만
../../.venv/Scripts/python test_headless.py          # 속도 명령 추종 점검
```
뷰어 조작: 마우스 왼쪽 드래그로 회전, 오른쪽 드래그로 이동, 휠로 확대·축소. 더블클릭하면 해당 물체를 선택한다.

## 파일
| 파일 | 내용 |
|---|---|
| `lite3_sim.py` | MuJoCo 1 kHz 물리, ONNX 정책(12 ms 주기), 서기 보간. 공식 C++ 배포 코드를 Python으로 옮김 |
| `lite3_edu_proto.py` | 학생용 API와 공통 로직(거리·각도 피드백, 경로 이탈 보정, 회전 재보정, 속도 상한, 넘어짐 감지) |
| `demo_square.py` | 학생 코드 예시(9차시 정사각형 걷기) |
| `test_headless.py` | 화면 없이 걷기 회귀 테스트 |
| `lite3_joint_proto.py` | **심화**: 관절(모터) 직접 조작 API, 정기구학·역기구학, 강성 조절 |
| `studio_web.py`, `web/`, `run_studio.bat` | **Lite3 Studio**: 편집기·3D 화면·조작 패널을 한 창에 (웹 UI, 앱 창) |
| `studio.py`, `control_panel.py`, `run_studio_classic.bat` | 클래식 tkinter 스튜디오 (MuJoCo 뷰어는 별도 창) |
| `lite3_interface.py` | 딥 로보틱스 공식 `RobotInterface`의 시뮬 구현 (GetJointPosition, SetJointCommand 12×5 등) |
| `sim_server.py`, `live.py` | 라이브 시뮬레이터: 3D 창과 물리를 계속 돌리며 받은 코드를 작업 스레드에서 실행. stdin JSON 명령, stdout 이벤트 |
| `joint_lessons/j1–j5_*.py` | 심화 예제: 모터 하나 → 자세 → 기구학 → 다리 들기(무게중심) → 트롯 걸음새 |

## 검증 결과 (2026-10-11, Windows 11, Python 3.12, MuJoCo 3.15, onnxruntime 1.31)
- 공식 `policy.onnx`로 넘어지지 않고 서기, 전후좌우 이동, 좌우 회전을 모두 수행했다.
- 화면 없이 실행하면 실시간보다 약 8배 빠르다(시뮬 17초가 약 2초). 3D 뷰어는 실시간으로 동작한다.
- 1 m 정사각형 4바퀴를 돈 뒤 원점 복귀 오차는 **약 1 cm, 방향 오차 ±5° 이내**. 개별 동작은 ±5 cm, ±3° 수준이다.

### 정책 특성 (측정값)
| 항목 | 값 | 대응 |
|---|---|---|
| 선속도 데드밴드 | 명령 < 약 0.2 m/s면 제자리걸음 | 명령 속도를 0.4 m/s로 고정(실제 약 0.3 m/s) |
| 회전 데드밴드 | 명령 < 약 20°/s면 거의 회전하지 않음 | 회전 명령 26–40°/s |
| 추종률 | 전진 약 75–85%, 회전 약 60–85% | 시간 기반이 아니라 **위치·yaw 피드백**으로 제어 |
| 정지 후 미끄러짐 | 3–5 cm, 회전 후 약 5° 되돌아감 | 정지 거리 선행(3 cm), 회전 재보정(최대 4회) |

## 한계와 다음 단계
- `sit()`은 아직 정지 동작으로 대신한다(앉기 보간은 미구현).
- 위치는 시뮬의 참값을 쓴다. 실물에서는 leg odometry(`/leg_odom2`)를 써야 하므로 오차가 더 커진다(10차시 수업 소재).
- 실물의 내장 보행은 데드밴드와 추종률이 다를 수 있다. 실물을 받으면 같은 측정을 반복해서 공통 로직의 상수를 백엔드별로 나눈다.
- 다음 단계: 가상 장애물과 `obstacle_ahead()`, 키보드 조종, 학생 PC 배포 패키지(설치 스크립트 1개).
