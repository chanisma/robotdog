# 학생용 Python 라이브러리 `lite3_edu` 설계안

목표: 기초 Python만 아는 고등학생이 **ROS2를 몰라도** 로봇을 조작할 수 있게 한다. 같은 코드가 세 환경에서 그대로 동작해야 한다.

## 1. 학생이 보는 코드
```python
from lite3_edu import Robot

dog = Robot("mock")        # "mock"(3D 시뮬) | "mock2d" | "real"

dog.stand()
for i in range(4):          # 정사각형 걷기
    dog.forward(1.0)        # 1 m 전진
    dog.turn_left(90)       # 90도 회전
dog.sit()
```

## 2. API (최소 세트)
| 분류 | 함수 | 설명 |
|---|---|---|
| 자세 | `stand()`, `sit()` | 서기, 앉기 |
| 이동 | `forward(m)`, `backward(m)`, `left(m)`, `right(m)` | 거리 단위 이동(블로킹, 끝날 때까지 기다림) |
| 회전 | `turn_left(deg)`, `turn_right(deg)` | 각도 단위 회전 |
| 기다리기 | `wait(sec)` | 정지 상태로 대기 |
| 센서 | `get_tilt()` → `(roll, pitch)`, `get_heading()` → yaw(°) | IMU 값 |
| 센서 | `get_battery()` | 배터리 잔량 % |
| 센서 | `obstacle_ahead()` → bool | ⚠️ 실물에서 값을 얻을 경로 확인 필요(초음파·깊이) |
| 고급 | `move(vx, vy, wz, sec)` | 속도를 직접 지정(속도 상한 적용) |

설계 원칙
- 단위는 **m와 도(°)**만 쓴다. 라디안이나 m/s는 감춘다(`move`만 예외).
- 모든 동작은 블로킹이다. 학생은 비동기나 스레드를 몰라도 된다.
- 오류 메시지는 한국어로 친절하게 보여 준다. 예: "속도가 너무 빨라요(최대 0.3 m/s)".
- 매 동작마다 화면에 실행 로그를 남긴다(디버깅 학습용).

## 3. 백엔드 구조
| 백엔드 | 구현 | 동작 환경 | 용도 |
|---|---|---|---|
| `mock` (= 3D 시뮬) | **MuJoCo + 공식 Lite3 3D 모델 + 공식 사전학습 보행 정책(`policy.onnx`)을 순수 Python으로 실행.** 실제 로봇 형상이 물리 법칙에 따라 걷는다. 가상 장애물과 IMU 제공 | **학생 PC(Windows 포함)**. `pip install mujoco onnxruntime numpy` | 매 차시 기본 실습 환경 |
| `mock2d` (예비) | matplotlib 위에서 내려다본 2D 화면. 실제 치수(610×370 mm)의 몸체 윤곽만 표시 | 사양이 낮은 PC | 3D가 안 돌아가는 경우 |
| `real` | 교사 PC의 게이트웨이 → ROS2 `/cmd_vel`, `/simple_cmd` → 로봇 내장 보행 | 교사 PC와 로봇 | 승인된 코드만 실행 |

### 3-1. 3D 시뮬의 근거 (2026-10-11 저장소 확인)
- 3D 모델: `deep_robotics_model/Lite3/mjcf/Lite3.xml` 또는 `Lite3_rl_deploy/Lite3_description/lite3_mjcf/mjcf/scene.xml`. 메시 8개, 약 7 MB.
- 보행 정책: `Lite3_rl_deploy/policy/ppo/policy.onnx`. 입력 `obs`, 출력 `actions`(관절 12개).
- 관측값 구성(`run_policy/lite3_test_policy_runner_onnx.cpp`): 몸체 각속도, 속도 명령, 관절 위치·속도, 직전 행동 등. 행동 = 기본 자세 + 행동 × 스케일(0.125 / 0.25 / 0.25) → PD 제어(kp 30, kd 1). 최대 명령 속도 0.8 m/s.
- C++ 배포 코드는 Ubuntu용이다. 하지만 위 로직은 짧아서 **Python으로 옮기면 Windows에서도 돌릴 수 있다**(MuJoCo와 onnxruntime 모두 Windows 휠 제공).

**✅ 프로토타입 검증 완료 (2026-10-11)**: Windows에서 Python만으로 공식 정책 보행과 학생 API를 실행했다. 1 m 정사각형 원점 복귀 오차는 약 1 cm다. 정책의 데드밴드(약 0.2 m/s, 20°/s 미만 무시)와 추종률 측정값은 [`sim/proto/README.md`](../../sim/proto/README.md)에 정리했다.

### 3-2. "같은 로직"의 범위
```
학생 코드 (dog.forward(1.0) ...)                    ← 모든 백엔드에서 100% 동일
────────────────────────────────────────────────
lite3_edu 공통 계층: 거리·각도 → 속도 명령 변환,
  yaw 피드백 회전, 속도 상한, 안전 정지 규칙           ← 100% 동일 (같은 코드 공유)
────────────────────────────────────────────────
드라이버: 속도 명령 전송, 센서 읽기 (이 부분만 다름)
  3D 시뮬: MuJoCo + RL 보행 정책
  실물:    ROS2 /cmd_vel → 로봇 내장 보행(비공개)      ← 보행 제어기는 서로 다름
```
- 로봇 내장 보행 제어기는 모션 호스트에서만 도는 비공개 프로그램이라 화면에 그대로 재현할 수 없다. 그래서 화면에서는 같은 속도 명령을 **공식 RL 정책**이 받아 걷는다.
- 그 결과 실물과 시뮬은 같은 명령에도 **이동 거리와 회전각에 약간의 차이**가 생긴다. 이 차이는 3단원 10차시("오차와 보정")의 수업 소재로 쓴다.
- 보행 제어기까지 똑같이 맞추고 싶다면 실물에서도 같은 `policy.onnx`를 rl_deploy로 실행하면 된다. 다만 이 경로는 관절을 직접 제어하므로 내장 안전 기능(장애물 정지 등)이 빠진다. **교사 시연·심화 과정 전용**으로 쓴다.
- `real` 백엔드에서 학생 PC는 로봇에 직접 붙지 않는다. **교사 PC 게이트웨이**가 코드를 받아 실행하고, 교사가 승인 버튼을 누른다.

## 4. 안전 계층 (real 백엔드)
- 속도 상한: 전진·횡이동 0.3 m/s, 회전 30°/s. 프로그램 한 번의 실행 시간은 최대 60초.
- 지오펜스: leg odometry 기준으로 시작점 반경 N m를 벗어나면 정지.
- 기울기가 임계값을 넘거나 배터리가 25% 아래로 떨어지면 자동으로 정지한 뒤 앉기.
- 하트비트가 끊기면 정지(로봇 쪽 타임아웃에 더해 소프트웨어에서도 한 번 더).
- 앱 Auto/Manual 전환과 물리 E-STOP이 **최상위 우선권**을 가진다.

## 5. 구현 순서
1. **프로토타입**: Windows에서 MuJoCo, Lite3 모델, `policy.onnx`를 Python으로 실행해 키보드 속도 명령으로 걷는지 검증한다(기술 위험 확인).
2. `mock` 3D 백엔드와 공통 API 계층. 실물 없이 만들 수 있고, 수업 3단원 전체를 커버한다.
3. `real` 게이트웨이. 실물을 받은 뒤 Phase 3에서 `/cmd_vel` 검증을 마치고 만든다.
4. `mock2d` 예비 백엔드(필요할 때만).
